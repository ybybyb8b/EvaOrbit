# Hermes 消息通道

## EO 业务工具连接

消息平台本身只收发消息，不能据此认定 Hermes 能操作 EO 业务。2026-11-06 已为本机 Hermes 另行接入 `mcp_servers.evaorbit`，使用正式 `/api/mcp`、OAuth 与现有 8 个通用业务工具；原有其他 MCP 连接保留。用户完成浏览器授权，凭据和刷新令牌由 Hermes 本机存储，未把消息通道令牌或服务端超级密钥用作业务授权。

生产既有 `evaorbit_mcp_access_token_hook` 原来只绑定一个 EO OAuth 客户端；迁移 `202611060006_hermes_mcp_audience.sql` 保留该标识并加入本次授权的 Hermes 公开客户端标识，为其签发 EO MCP 专属 audience。普通登录、其他 OAuth 客户端及其余 claims 保持；不能改为接受任意 authenticated audience。该迁移已应用，刷新后的凭据已核对 audience 和 EO 配对账户一致。

Hermes 官方连接测试发现 8 个工具；通过同一 OAuth 凭据实际验证资源发现、Schema、任务读取及临时 Inbox 创建／读取／删除，临时记录已移除，零模型调用。在定时任务结束、网关空闲后通过官方命令安全重载，网关恢复 ready。现有对话下一轮可使用业务工具，不需要重新打 IPA；模型是否正确选择工具及实际便利贴处理仍需用户体验验收。记录使用各资源的 Schema 与日期精度规则；接入工具不等于保证模型会自动执行每张纸条，也不能把失败回复当成已完成业务写入。

EO 是 Hermes 的消息平台。EO 保存用户输入、助手回复、投递／处理回执；Hermes 负责模型、历史上下文、记忆和工具执行。EO 不给 Hermes 重发整段历史，不附加旧 Persona 或另一套工具循环。详细运行日志和模型提供的推理内容保留本机。

## 组成

- `/ai` 使用共享 `HermesChat`，便利贴在 Hermes 页填写和查看；旧 `/ai/papers` 转至 `/ai`，原 AI 处理入口停用，历史数据保留。Home Log 仅保留原来的 2×5 记录按钮，不再展示纸条输入区。
- `GET/POST /api/hermes` 复用账户认证及账户头校验，经受限 `eo_hermes` RPC 管理消息。首次发送提供会话 UUID 和消息 UUID，响应丢失后复用 ID；新对话使用新 UUID。
- `hermes_connections` 保存可撤销凭据的 SHA-256、工作实例和心跳；`hermes_conversations`／`hermes_messages` 保存云端聊天副本和投递状态。不复用旧模型调用表，也不自动导入旧聊天。三表不进入生活数据备份；清理云端聊天不删除 Hermes 本地会话或记忆。
- `integrations/hermes-evaorbit` 为 Hermes `kind: platform` 插件，使用正式 `BasePlatformAdapter`、`MessageEvent` 和生命周期钩子。只需 stdlib 加 Hermes 已有依赖，不新增 Python 网络或 Supabase SDK。原始通道凭据只在下载连接文件和电脑 `.env` 中出现，数据库只存哈希；不用 service-role key。

## 连接与运行

1. 应用 `202611060001_hermes_channel.sql`，发布配套 Web/API。本地包还需重建后使用新的精确 GET/POST `/api/hermes` 白名单；不改 bridge、权限、签名或 Tracker 同步。未发布／未迁移时显示明确不可用，不回退到旧模型处理器。
2. 在电脑浏览器打开 Hermes，点击“连接 Hermes”，下载连接文件。已有连接会要求确认凭据轮换，旧令牌立即失效。
3. Windows 复用现有 Hermes 托管环境安装：

   ```powershell
   ./integrations/hermes-evaorbit/install.ps1 -HermesHome "$env:LOCALAPPDATA/hermes" -PairingFile <连接文件路径>
   ```

   `HermesHome` 指实际用户数据目录，不是源码目录或旧备份目录；自定义安装先从当前运行环境确认。安装器备份 `config.yaml`、`.env` 及被替换的插件文件；保留其他插件、模型、其他平台和环境行，保留 YAML 注释；只添加 EO 平台启用项和四项 EO 环境变量。不会停止、重启或修复正在运行的 Hermes，不修改其记忆、会话或核心源码。当前 Hermes 的插件热加载只重接已有适配器的处理器，新消息平台仍需网关重新启动后建立连接；操作前确认无运行中任务并取得用户同意，不关闭桌面应用。
4. Hermes Gateway 加载 `evaorbit-platform` 后通过出站 HTTPS 连接 Supabase，不需要公网 IP、开放端口、额外服务器或隧道。`EO_ALLOWED_USERS` 必须与配对账户一致。需要默认主动消息目的地时配置 `EO_HOME_CHAT=<EO 会话 UUID>`；Gateway 外的 Cron 通过插件 `standalone_sender_fn` 发送。

## 回执、恢复和费用边界

- 保存成功只代表云端收到，状态仍为 queued；电脑领取后为 received；实际开始处理为 processing。只有助手回复写入成功，成功完成回执才允许显示 done。失败、取消或没有确认回复分别保留错误或中断状态。
- 每段对话同时只领取一条消息；不同对话有独立 Hermes 来源标识。工作实例通过心跳续约；过期和重启遗留工作显示 interrupted，不自动重放可能已经执行过工具的输入。人工重试生成新 attempt ID，旧尝试的回复不能覆盖新尝试。
- EvaOrbit 的原始发送时间取消息首次保存的 `created_at`。适配器把它交给 Hermes 保存，在组装模型请求时为 EvaOrbit 用户消息加入带 UTC 偏移的 ISO 8601 `sent-at`。重载按 Hermes 历史各条消息的时间重放，重试仍使用同一原始时间。发送时间与原文分开保存，澄清回答通过工具结果的 `user_message_sent_at` 传入。只由网关执行的命令没有模型请求。保留输入的首尾空白需要应用 `202611060007_hermes_message_metadata.sql` 和对应的 Web/API。
- 已生成的发送与完成回执先写本机 SQLite outbox，网络失败后按原 UUID 重传，云端幂等。明确清理或重试已使回复过期时，丢弃旧投递并报告未送达；不伪称发送成功。
- 本阶段使用轻量增量轮询：插件空闲每五秒只查询待收消息，独立每二十五秒心跳；EO 前台每五秒读取消息增量和未完成消息状态，后台页停止。连接凭据不随查询参数发送，不逐 Token 写数据库，不轮询模型，不上传完整工具轨迹。Realtime 可后续替换唤醒机制，持久消息和去重契约不变。
- EO 可在电脑离线时留言，排队不消耗模型 Token。模型费用和工具权限由现有 Hermes 配置决定。云端历史分页读取；清理对话会取消未领取消息，正在处理时阻止清理，以免丢失回复目的地。云端清理不承诺立即清除平台备份。

## 消息展示与便利贴

`202611060003_hermes_activity.sql` 增加全局状态摘要与账户隔离的 `hermes_reads` 已读游标。`HermesActivity` 在已登录的 Web／本地壳内常驻，支持拖动贴边与按账户保存相对位置；表单及选项浮卡出现时暂时避让。点击查看近期对话、排队／处理／待回答／失败和真实报错，并可直接进入对应对话。未读在消息区确实滚动到末尾且页面可见时才确认，不因打开状态面板而清除。位置以外不把正文写入浏览器存储。

空闲状态每 15 秒查询轻量摘要，有任务时每 5 秒查询；页面不可见时暂停，并在回到前台恢复。发送事件即时显示提交中／已保存／未确认，响应丢失时可以按消息 ID 查询保存回执，不自动重发。Native 的 Hermes 写入不触发无关 Home 快照刷新。仅是应用内常驻入口，不是 iOS 应用外悬浮窗或锁屏后台执行保证。

`202611060002_hermes_message_surfaces.sql` 增加有容量限制的消息 `presentation`。用户只能通过发送操作标记便利贴，不能伪造助手、思考内容或提问卡。Hermes 页的便利贴和普通对话使用同一消息通道；便利贴列表按当前对话分页查找。独立 Papers 页面转至 `/ai`，旧 API 仅保留幂等存入 Inbox 的兼容动作，不能开启、重试或恢复旧 AI 整理；历史数据不删除。

Hermes 页输入区便利贴入口展开独立的 `HermesNoteSheet`，顶部入口查看便利贴记录，不改变普通聊天草稿。采用用户提供样张第三排中间的淡紫纸／绿色胶带款，经图片编辑提取的透明素材位于 `public/textures/hermes-note-lavender-green.png`；纸面仅叠加可编辑文字；不显示标题或外层面板，右上角为 Reicon 关闭按钮，底部两按钮独立悬浮。纸张按可用视口缩放，外层无横向或纵向滚动区域，仅正文可在纸内滚动。暂时关闭保留当前页面的便利贴草稿，发送失败也保留正文及同一请求 ID；成功后才清空便利贴，不清空普通聊天输入。本地 Host 使用同一组件，须安装本轮重建包后使用。

Hermes 提供的本地化 reasoning 消息封套在适配器发送前拆成独立展示字段，默认折叠。没有收到的思考内容不生成，普通代码、HTML 标签不猜作思考链。Hermes 自身仍决定是否显示推理，且当前网关投影最多保留前 15 行，并不代表完整内部过程。EO 不逐 Token 上传内容。

工具执行在每轮用户消息下方显示为一个默认折叠的摘要。适配器每四秒合并同步有变化的调用计数和执行状态，展开最多显示调用次数最多的 12 个工具名称，其他调用合并计数。参数、输出和详细错误保留在 Hermes。摘要随最终回执保存，按消息的处理尝试隔离。此功能需要应用 `202611060009_hermes_tool_activity.sql` 并更新 Hermes 适配器。

带网关状态标记的通知和自我改进摘要使用居中的系统提示，不计作回复或触发 Bark。已存的常见自我改进摘要可在对话中按系统提示显示。Hermes 的 Markdown 代码块使用聊天主题配色，长行可在代码区域内横向滚动。

提问卡由真实 `send_clarify` 生成，支持单选、多选和手填。选择绑定同账户、同对话及提问 ID，通过独立 response 消息绕过当前等待中的普通消息队列，在电脑核实仍有效的 Hermes session 后调用官方澄清解析器；不是新增模型请求，也不把按钮文字当执行授权。回执落盘后更新卡片，超时或网关重载会失效，历史卡片不能再次选择。执行审批继续沿用 Hermes 的现有命令流程，不从普通 Markdown 自动生成授权按钮。
