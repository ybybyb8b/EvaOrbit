# Eva 纸条后台

## 入口和边界

Home 通用 Log 弹窗顶部直接输入纸条，下面保留原有分类。初始两行，随文字增加扩高（最高 34dvh / 260px），之后框内滚动；删减文字自动收回。Vintage 使用主题的内凹输入材质，浅色补充同语义的凹陷表面。

“仅存 Inbox”不调用模型；“交给 Eva”才创建后台整理请求。总开关位于原 `/ai` 页面，默认关闭；开启不会扫描历史，也不会处理普通 Inbox、Task、Food 等入口的写入。桌面旧唤醒入口统一进入工作台，原聊天数据和兼容 API 保留。

纸条原文保存到 `inbox_items`；`eva_jobs` 仅增加处理身份、原文审计快照、状态、同纸条补充及结果引用，不构造另一套任务。明确事项原子创建现有 Task 及明确要求的提醒；其余留 Inbox 或待确认。不同纸条互不共享模型上下文，纸条内部最多保留最近四条补充，每条 1500 字。已部分创建的纸条不能重新解析，避免新结果与已应用任务错配；已建任务通过链接编辑，剩余建议可确认或放弃。

## 调用与可靠性

- `POST /api/eva` 支持 capture、settings、retry、revise、approve、keep、resume；GET 仅读取，`?view=status` 仅读开关，不发起模型调用。
- 先事务保存 Inbox 原文与 UUID 请求，再通过 Next `after` 处理。不依赖浏览器持续打开，不使用请求断开 signal。
- 每次尝试只发一个非流式 Chat Completions 请求，45 秒超时、2500 输出 Token 上限；无工具清单、Persona、Graph、全局聊天或全库数据读取。模型需支持兼容协议与 JSON 输出。
- 固定提示词在 `src/lib/eva.ts`，捕获时间和内容置于后面的用户消息；不为凑缓存长度填充提示词。缓存是否生效由 Provider 决定，取其真实 usage。
- 以捕获时刻和上海时区解释相对日期，重试不会把“明天”向后挪。结构化结果校验字段、真实日期、逐字原文依据及重复事项；仅日期保持时间 null。明确提醒同时要求日期、时间、提醒意图证据。
- 租约两分钟、每纸条最多十次尝试；领取和提交均有状态／租约校验，提交再次检查总开关。任务、提醒、结果引用与 Inbox 状态在同一事务内保存。人工确认只补尚未应用的建议。
- 平台硬中断后原文和排队状态仍在；工作台通过用户主动“继续整理”恢复至多三张。没有另建 Cron、无人值守常驻服务或自动重试付费调用。关闭开关不重新领取，正在返回的结果不写业务记录；已完成记录保留。

## 处理反馈

只有明确交给 Eva、重试或补充同张纸条才出现临时浮动入口；纯存散落不出现。入口可拖动并贴边，跨页面保留，发送转圈、等待模型的轻微点动画、收到结果的短暂反馈分别表示状态；遵循减少动态效果设置。多张纸条合并计数，点击沿用 FormSheet 查看原文、结果、待确认项和诊断；已查看的成功回执关闭后消失，失败与待确认保留到用户收起。收起不取消后台处理。

`eva_calls.usage.feedback` 保存当前尝试的阶段、Provider／模型、请求及接口响应时间、HTTP 状态、Request ID 和受限脱敏错误。纸条保存成功、已发起模型请求、接口响应、收到模型回复是独立事实；没有响应时不声称已经送达，网络中断后的提交结果显示待确认。凭据、限流、超时、解析／校验、保存失败分别展示；可复制诊断，不复制纸条正文、密钥或响应原始正文。重试排队期间不沿用旧尝试的错误反馈，无需新增表或迁移。

浮动入口只在账户隔离的 sessionStorage 保存最近二十个纸条 ID，不保存正文。`GET /api/eva?view=jobs&ids=…` 按账户查询这些纸条及最新尝试；有待处理项时每 2.5 秒查询，三分钟后停止定时查询，回到前台／恢复网络或手动刷新时再次确认。查询不调用模型，不自动重试收费请求；租约过期提示可能中断，由用户主动恢复。本功能不提供 App 退出后的系统推送。

## 用量、备份与本地版

`eva_calls` 按尝试独立留存，覆盖失败或未知用量；输入、输出、缓存 Token 不混算。可选配置准确模型 ID 的每百万 Token 价格、币种及版本，调用记录保留当时的计价快照。缺少 usage、缓存明细或对应价格时保留未知；费用是按价格表计算的估算，不声称等于供应商账单。工作台按上海自然日／月、模型和币种分别汇总。

当前低频个人规模直接读取调用账本作汇总；若长期数据接近本地业务响应的 8 MiB 上限，再将汇总移到数据库分页／聚合。日常仅在有排队／运行纸条时轮询，不发模型调用。

备份版本 17 增加 `eva_jobs`／`eva_calls`，兼容旧备份为空；恢复 SQLite 时清理租约并将 running／queued 改为 held，避免恢复触发写入。运行开关及当前价格属于 `eva_settings`，不随业务备份恢复。

本地 React 共享同一输入与工作台，仅通过账户绑定 `business.request` 白名单 GET／POST `/api/eva` 在线操作，不增加离线队列、Bridge 方法、权限或 entitlement。新白名单随包更新，旧 IPA 不支持新路径，需新本地包。断网不提交；读取的状态只是访问缓存，不代表设备可在后台运行 AI。
